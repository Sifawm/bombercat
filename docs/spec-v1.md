# Spec: BomberCat v1

- **Status:** ready-for-agent
- **Date:** 2026-10-09
- **Vocabulary:** [CONTEXT.md](../CONTEXT.md) — use these terms exactly, in code and in prose.
- **Companion documents:** [v1-scope.md](./v1-scope.md) (agreed values at a glance),
  [powerups.md](./powerups.md) (Powerup catalogue and status),
  [ADR 0001](./adr/0001-map-studio-in-godot-editor.md), [ADR 0002](./adr/0002-rules-layer-owns-movement.md).

## Problem Statement

The creator wants a Bomberman-style game starring five cats, playable by two people on the same
computer. Today the project only has the art starting point: five rigged and animated Cat models,
a Bomb, floor, wall and crate models, all generated by Blender Python scripts, plus reference
renders. There is no game, no way to author Maps, no Powerups, and nothing that moves or sounds
when played.

## Solution

BomberCat v1: a local two-Player Battle game built in Godot. Two Players each pick a Cat, then
fight a best-of-3 Match on the `backyard` Map, placing Bombs, breaking Crates and collecting
cat-themed Powerups. The game feels alive: Bombs pulse faster as their Fuse runs out, Powerups
float, Explosions shake the screen, and everything has sound. The creator authors Maps in
Map Studio, a workspace inside the Godot editor that players never receive. The game runs on
Linux and Windows desktop and in a web browser.

## User Stories

### Starting a Match

1. As a Player, I want a Title screen with the game's logo and animated Cats, so that I know what I am about to play.
2. As a Player, I want a Play option on the Title screen, so that I can start a Match.
3. As a Player, I want a Quit option on the Title screen, so that I can close the game.
4. As a Player, I want a How to Play card reachable from the Title screen, so that I can learn the controls and what each Powerup does before playing.
5. As a Player, I want to see the five Cats in 3D with their names on Cat Select, so that I can choose one I like.
6. As a Player, I want my own cursor with my own colour on Cat Select, so that I can choose at the same time as the other Player.
7. As a Player, I want to confirm my Cat with my bomb button, so that I do not need to learn extra controls for menus.
8. As a Player, I want my chosen Cat to play its celebration animation, so that I get feedback that my choice was registered.
9. As a Player, I want a Cat already confirmed by the other Player to be locked, so that the two Cats are always distinguishable during a Round.
10. As a Player, I want a Random option on Cat Select, so that I can let the game choose for me.
11. As a Player, I want a short countdown once both Players have confirmed, so that the Match does not start abruptly.
12. As a Player, I want to navigate every menu with the same keys or gamepad I play with, so that I never need the mouse.

### Controlling a Cat

13. As Player 1, I want to move with WASD and place Bombs with Space, so that I can share a keyboard with Player 2.
14. As Player 2, I want to move with the arrow keys and place Bombs with Enter, so that I can share a keyboard with Player 1.
15. As a Player, I want to use a gamepad (stick or d-pad, A to place a Bomb) instead of the keyboard, so that I can play more comfortably.
16. As a Player, I want keyboard and gamepad to both work without configuring anything, so that I can just pick one up and play.
17. As a Player, I want my Cat to move smoothly in four directions, so that I can dodge an Explosion by half a step.
18. As a Player, I want my Cat to slide into a corridor when I turn slightly early or late, so that Walls do not snag me at corners.
19. As a Player, I want up on my device to be up on the screen, so that controls feel straight.
20. As a Player, I want my Cat to face the direction it walks and play its walk animation, so that movement reads clearly.
21. As a Player, I want a meow button that makes my Cat meow with a speech bubble, so that I can taunt the other Player.

### Bombs and Explosions

22. As a Player, I want to place a Bomb on the Tile my Cat stands on, so that I can attack and break Crates.
23. As a Player, I want my Cat to play its place-bomb animation, so that the action feels physical.
24. As a Player, I want to be limited to my Bomb Capacity, so that Bombs are a resource to manage.
25. As a Player, I want a Bomb to explode when its Fuse ends, so that I can time my attacks.
26. As a Player, I want the Bomb to pulse and blink faster as its Fuse runs out, so that I can see how long I have without a number.
27. As a Player, I want to hear the Fuse tick speed up, so that I can sense danger without looking.
28. As a Player, I want to walk off the Tile of the Bomb I just placed, so that placing a Bomb does not trap me.
29. As a Player, I want Bombs to block movement for everyone once I have left their Tile, so that I can use them to corner the other Cat.
30. As a Player, I want an Explosion to spread in a cross up to my Range, so that I can predict which Tiles are dangerous.
31. As a Player, I want Walls to stop an Explosion, so that I can take cover behind them.
32. As a Player, I want an Explosion to destroy the first Crate it reaches and stop there, so that Crates are cleared one layer at a time.
33. As a Player, I want an Explosion to detonate any other Bomb it reaches immediately, so that I can set up Chain Reactions.
34. As a Player, I want an Explosion to stay lethal for a short moment, so that walking into fresh fire is punished.
35. As a Player, I want my own Explosions to be able to kill me, so that careless play has a cost.
36. As a Player, I want an Explosion to destroy Powerups lying on the floor, so that I must choose between bombing and collecting.
37. As a Player, I want the Explosion to grow outwards with a flash, particles and smoke, so that it feels powerful.
38. As a Player, I want the screen to shake briefly on each Explosion, so that impacts are felt.
39. As a Player, I want a Crate to break into pieces when destroyed, so that destruction is satisfying.

### Powerups

40. As a Player, I want some Crates to reveal a Powerup when destroyed, so that breaking Crates is rewarding.
41. As a Player, I want a revealed Powerup to pop out of the Crate, so that I notice it appeared.
42. As a Player, I want Powerups to float, spin and glow, so that they catch my eye.
43. As a Player, I want to collect a Powerup by walking over it, so that collecting needs no extra button.
44. As a Player, I want a pop, a rising icon and a sound when I collect a Powerup, so that I know what I got.
45. As a Player, I want a Yarn Ball to raise my Bomb Capacity by 1, so that I can place more Bombs at once.
46. As a Player, I want a Tuna Can to raise my Range by 1, so that my Explosions reach further.
47. As a Player, I want Catnip to make my Cat faster, with a visible trail, so that I can outrun the other Cat.
48. As a Player, I want Paw Swipe to let me push a Bomb by walking into it, so that I can send Bombs at the other Cat.
49. As a Player, I want a pushed Bomb to slide until it hits something and then stop, so that I can aim it down a corridor.
50. As a Player, I want Nine Lives to let me survive one Explosion, so that I get a second chance.
51. As a Player, I want a visible aura while I hold Nine Lives, so that both Players know I am protected.
52. As a Player, I want to blink and be briefly invulnerable after Nine Lives absorbs a hit, so that the same Explosion does not kill me anyway.
53. As a Player, I want Nine Lives not to stack, so that no Cat becomes unkillable.
54. As a Player, I want a Cucumber to put a random Curse on whoever collects it, so that grabbing everything blindly is risky.
55. As a Player, I want a Curse to be inverted controls or slowness for about 10 seconds, so that it is a real but temporary handicap.
56. As a Player, I want a cursed Cat to show a dizzy spiral and a green tint, so that both Players can see who is cursed.
57. As a Player, I want Bomb Capacity and Range to have a maximum, so that a Round cannot snowball without limit.
58. As a Player, I want the same quantities of each Powerup every Round with only their positions changing, so that Rounds are fair but never identical.
59. As a Player, I want Powerups to look clearly different from each other in shape and colour, so that I can identify them at a glance.

### Rounds and Matches

60. As a Player, I want the Cats to drop onto their Spawn Points followed by a "3, 2, 1, Go!", so that both Players start at the same instant.
61. As a Player, I want to start in a corner far from the other Cat with room to escape my first Bomb, so that the opening is fair.
62. As a Player, I want a Round to end when only one Cat is alive, so that there is a clear winner.
63. As a Player, I want my Cat to play its death animation with a comic meow when killed, so that losing is still funny.
64. As a Player, I want a moment of slow motion and zoom on the final elimination, so that the decisive moment is celebrated.
65. As a Player, I want a banner naming the winning Cat after each Round, so that the result is unmistakable.
66. As a Player, I want a Round to be a Draw when both Cats die in the same Explosion, so that mutual kills reward nobody.
67. As a Player, I want a visible Round timer of 2 minutes, so that I know how long is left.
68. As a Player, I want the timer to pulse and the music to speed up near the end, so that I feel the pressure.
69. As a Player, I want a Round that runs out of time to be a Draw, so that hiding does not win.
70. As a Player, I want a Draw to be replayed without awarding a win, so that a Match always has a winner.
71. As a Player, I want the Map restored and all Powerups lost at the start of each Round, so that every Round starts even.
72. As a Player, I want the first Cat to win 2 Rounds to win the Match, so that one lucky Round does not decide everything.
73. As a Player, I want the HUD to show each Player's portrait, Rounds won and Powerups held, so that I can read the state of the Match at a glance.
74. As a Player, I want the next Round to start automatically after the result banner, so that the Match keeps its pace.
75. As a Player, I want a Match Result screen with the winning Cat celebrating, so that winning feels rewarded.
76. As a Player, I want a per-Player summary of Bombs placed, Crates destroyed and Powerups collected, so that we can compare how we played.
77. As a Player, I want a Rematch option that keeps the same Cats, so that we can play again immediately.
78. As a Player, I want a Back to Cat Select option, so that we can change Cats.

### Pause, audio and display

79. As a Player, I want to pause with Esc or Start, so that real life can interrupt a Round.
80. As a Player, I want Resume and Quit to Title in the Pause menu, so that I can continue or leave.
81. As a Player, I want the How to Play card available from the Pause menu, so that I can check what a Powerup does mid-Match.
82. As a Player, I want to switch music and sound effects on or off independently from the Pause menu, so that I can play quietly.
83. As a Player, I want calm music on the menus and lively music during a Round, so that each part has its own mood.
84. As a Player, I want a distinct sound for every game event (place, explode, break, collect, curse, swipe, shield, death, victory, meow), so that I can follow the Round by ear.
85. As a Player, I want UI sounds for moving, confirming and cancelling, so that menus feel responsive.
86. As a Player, I want smooth transitions between screens and buttons that react, so that the game feels polished.
87. As a Player, I want the whole Map visible at all times on one shared screen, so that neither Player is ever off camera.
88. As a Player, I want the game to keep its 16:9 picture on any window size, so that nothing is cut off or stretched.
89. As a Player, I want F11 to toggle fullscreen, so that I can choose how to play.
90. As a Player, I want to play in a web browser from a link, so that I can try the game without installing it.
91. As a Player, I want native Linux and Windows builds, so that I can play offline at full quality.

### Creating Maps (Map Studio)

92. As the creator, I want to paint Floor, Walls, Crates and Spawn Points on a grid with the real models, so that I see the Map exactly as it will be played.
93. As the creator, I want to choose a Wall's visual variant (brick, low brick, pillar), so that Maps look varied without changing the rules.
94. As the creator, I want a visible Spawn Point marker that only appears in Map Studio, so that I can place starts without them showing in the game.
95. As the creator, I want each Map saved as its own text file, so that I can version Maps in git.
96. As the creator, I want to define each Map's Powerup Pool, so that each Map can have its own character.
97. As the creator, I want a warning when a Map has fewer than 2 Spawn Points, so that I never ship an unplayable Map.
98. As the creator, I want a warning when a Spawn Point has no room to escape its first Bomb, so that no Player starts doomed.
99. As the creator, I want a warning when the Powerup Pool holds more Powerups than the Map has Crates, so that the pool always fits.
100. As the creator, I want to test-play the Map I have open with one key, so that I can iterate quickly.
101. As the creator, I want a Map to declare more Spawn Points than Players, so that the same Map works when more Players are added later.
102. As the creator, I want Map Studio excluded from exported builds, so that players only receive the game.
103. As the creator, I want the `backyard` Map (13 x 11, brick border, checkerboard pillars, 4 corner Spawn Points, symmetric Crates), so that v1 ships with a classic, fair Map.

### Art, tuning and maintenance

104. As the creator, I want every model generated by a Blender script, so that any model can be regenerated and changed reproducibly.
105. As the creator, I want models for the six v1 Powerups, the Spawn Point marker and the low brick Wall, so that every game element has its art.
106. As the creator, I want every asset, script, identifier and document named in English, so that the project follows the common standard.
107. As the creator, I want all balance values (Fuse, speeds, Range, caps, Curse duration, Round time) in one place editable without touching code, so that I can tune the feel by playing.
108. As the creator, I want every audio file listed with its origin and licence, so that the game can be published without legal doubt.
109. As the creator, I want the Powerup catalogue's status columns kept up to date, so that I can see which Powerups are modelled and which work in game.
110. As a developer, I want the game rules to run without any scene, so that I can test them quickly and automatically.
111. As a developer, I want a Cat to be driven by commands from a Player controller rather than by reading input devices, so that an AI or a remote Player can be added later without changing the Cat.
112. As a developer, I want adding a Powerup to mean adding one new piece rather than editing existing ones, so that the backlog in the catalogue can be built incrementally.
113. As a developer, I want the same sequence of commands to always produce the same Round, so that bugs can be reproduced and online play stays possible.

## Implementation Decisions

### Platform and conventions

- Godot 4.7, GDScript with static typing mandatory (untyped declarations treated as errors), Compatibility renderer.
- Targets: Linux and Windows desktop (primary), web (secondary). Base resolution 1920 x 1080, aspect kept with letterboxing.
- All files, identifiers, comments and documents are in English. Code follows SOLID.
- The repository holds the Godot project in its own folder, separate from the Blender sources and the reference renders, so that Godot only imports game assets. Blender scripts export GLB files directly into the game's asset folder.

### Architecture: three layers, one-way dependencies (ADR 0002)

- **Rules layer** — plain classes with no nodes or scenes. It depends on nothing else. It owns all game state and decides everything.
- **Presentation layer** — scenes that subscribe to the rules layer's signals and read its state to place models, play animations, particles and sound, and draw the HUD and screens. It never decides game outcomes and contains no gameplay colliders.
- **Control layer** — Player controllers that turn a device into commands. v1 has one implementation (local human); AI and remote Players are future implementations of the same base.

### Rules layer modules

- **Board** — the grid of Tiles: what occupies each one (Floor, Wall, Crate, Bomb, Powerup, active Explosion) and queries such as "is this Tile walkable for this Cat". Built from a Map's data.
- **Cat state** — position (continuous, in Tile units), facing, alive flag, Bomb Capacity, Range, speed, held effects (Paw Swipe, Nine Lives, active Curse, invulnerability).
- **Movement** — advances a Cat along the grid from a movement command with a fixed time step. A Cat may move within a Tile it already overlaps and may not enter an occupied one, which yields the "owner may leave its Bomb's Tile but not re-enter" rule. Includes corner assist. No Godot physics.
- **Bombs and Explosions** — placing against Bomb Capacity, Fuse countdown, computing the cross of Tiles from Range, stopping at Walls and at the first Crate, Chain Reactions, Explosion lifetime, killing Cats on affected Tiles, destroying floor Powerups, sliding of pushed Bombs.
- **Powerups** — each Powerup is its own small class sharing one base ("apply to a Cat"), so new ones are added without modifying existing ones. Curses follow the same pattern.
- **Powerup Pool distribution** — assigns a Map's fixed pool to random Crates at Round start, using an injectable random source so tests can fix the outcome.
- **Round** — ties the above together: accepts commands per Player, advances by a fixed time step, tracks the time limit, and determines the outcome (winner or Draw).
- **Match** — counts Round wins, replays Draws, declares the Match winner at 2 wins, and assigns Spawn Points (one per Player, farthest apart).
- **Game configuration** — one resource holding every tunable value; the rules receive it rather than hard-coding numbers.

### Rules layer interface (the contract the other layers use)

- **Commands in:** per Player, a movement direction (or none) and "place Bomb". The meow is presentation-only and does not enter the rules.
- **Advance:** a single "step by fixed delta" call drives the whole simulation.
- **Signals out:** Bomb placed, Bomb moved, Bomb detonated (with affected Tiles), Crate destroyed, Powerup revealed, Powerup collected, Powerup destroyed, Curse started/ended, Nine Lives consumed, Cat eliminated, Round ended (winner or Draw), Match ended.
- **State out:** read-only access to the Board and Cat states, used by presentation each frame and by a future AI.

### Maps and Map Studio (ADR 0001)

- A Map is a Godot scene containing a GridMap painted with a mesh palette (floor, wall variants, crate, spawn marker) plus its Powerup Pool as exported data.
- A loader converts a Map scene into the plain data the Board is built from; this is the only place that knows about GridMap. The rules layer never sees a scene.
- Floor is laid automatically in a two-tone checkerboard under every Tile.
- Map Studio consists of the palette, a tool script that reports validation problems as editor configuration warnings, and a test-play entry point. Its folder is excluded from export presets.
- Validation rules: at least 2 Spawn Points; each Spawn Point has an L of free Tiles; the Powerup Pool does not exceed the Crate count; the Map is enclosed by Walls.

### Presentation

- Camera: fixed, facing north from about 55-60 degrees, no yaw, narrow field of view, framing the whole Map. Screen shake and final-elimination slow motion are presentation effects only and never alter the rules' time step.
- Cat skeletal animations come from the existing GLB actions. All other motion is tweens, shaders and particles driven by rules signals and state — notably the Bomb pulse, whose rate is a function of remaining Fuse.
- Audio: two buses (music, effects), CC0 sources only, catalogued in a credits document.
- Screens: Title, Cat Select, Round (with HUD), Round Result overlay, Match Result, Pause, How to Play. UI text in English.
- Fixed input bindings: Player 1 WASD / Space / Q or gamepad 1; Player 2 arrows / Enter / Right Shift or gamepad 2.

### Art pipeline

- Models remain generated by Blender Python scripts using vertex colours and no textures. Existing Spanish-named scripts, functions and GLB files are renamed to English; Cats are named after their characters (`turing`, `berni`, `aquiles`, `hami`, `ada`).
- New models: `yarn_ball`, `tuna_can`, `catnip`, `paw_swipe`, `nine_lives`, `cucumber`, `spawn_marker`, `wall_brick_low`. Each Powerup is the object itself with a distinct silhouette and dominant colour.
- Crate fragments, smoke, sparks and fire are particles and shaders, not models.

### Agreed starting values (all tunable)

Bomb Capacity 1, Range 2, Fuse 3 s, Explosion lifetime 0.5 s, Round limit 2:00, caps of 8 for
Bomb Capacity and Range, Curse duration 10 s. `backyard` Powerup Pool: Yarn Ball 6, Tuna Can 6,
Catnip 4, Paw Swipe 2, Nine Lives 1, Cucumber 2.

### Build order

Seven stages, each ending in something playable or verifiable, with a stop to show the creator
after each: (1) foundations, (2) playable core, (3) Map Studio and `backyard`, (4) Powerups,
(5) Match and screens, (6) polish, (7) export. Simple versions of the Bomb pulse and Powerup float
are included in stages 2 and 4 rather than left for stage 6.

## Testing Decisions

- **One seam:** the rules layer's public interface — commands in, fixed-step advance, signals and state out. Tests build a small Board from plain data, issue commands, step the simulation, and assert on emitted signals and resulting state. Because the rules own movement and need no scene, this single seam covers every gameplay rule.
- **What makes a good test here:** it describes a game situation in domain terms and checks the observable outcome, never internal structure. Example: "a Bomb with Range 2 next to a Crate: the Crate is destroyed and the Tile behind it is not in the Explosion".
- **Modules covered through that seam:** Board, movement (including leaving and not re-entering a Bomb's Tile, and corner assist), Bombs and Explosions (Walls, Crates, Chain Reactions, self-kill, floor Powerups), each Powerup and Curse, caps, Powerup Pool distribution with a fixed random source, Round outcomes (win, both-die Draw, time-out Draw), Match scoring and Draw replay, Spawn Point assignment.
- **Map validation** is tested at the same level on plain Map data: missing Spawn Points, no escape room, oversized pool.
- **Not automatically tested:** presentation, audio, screens and the feel of the controls — verified by playing at the end of each stage.
- **Tooling:** plain test scripts run with Godot in headless mode, exiting non-zero on failure. No test framework is added until this stops being enough.
- **Prior art:** none; the repository has no tests or game code yet.

## Out of Scope

- AI Players, online multiplayer and more than 2 Players (the architecture leaves room; nothing is built).
- A campaign or any mode other than Battle.
- Sudden death, per-Cat abilities, per-Cat voices.
- Powerups beyond the six of v1 (see the backlog in the Powerup catalogue).
- Special Tiles (conveyors, teleports, ice, holes) and Maps other than `backyard`; map selection screen.
- Options screen, key remapping, persistent statistics, attract mode, translations.
- Mobile and touch controls; store distribution; hosting of the web build.
- New Cat skeletal animations.

## Further Notes

### State of the repository when this spec was written

- Nothing of the game is built. No Godot project exists yet.
- Present: the Blender scripts and exported GLB files for the five Cats (with `idle`, `walk`, `place_bomb`, `die`, `win` actions), the Bomb, two floors, a pillar, a crate and a brick wall, still under Spanish names in a `models` folder; reference renders; this documentation.
- Git is initialised locally on `main` with a `.gitignore`, but **there are no commits**. The first action of stage 1 is to commit the current state before moving or renaming anything.
- The existing models are sized for a 1 m grid; Cats are about 1.2 m tall and were scaled to 0.72 in the reference render to fit a Tile.
- The reference game render uses a 45-degree isometric camera. That view is kept for the Title screen and promotional renders only; gameplay uses the unrotated tilted camera.

### How to resume in a new session

Read `CONTEXT.md`, this spec and the two ADRs, then start at stage 1 (foundations). The creator
had not yet given the final go-ahead to begin stage 1 when this spec was written, so confirm
before restructuring the repository.

### Known risks to check early

- The feel of movement and corner assist is hand-tuned; validate it at the end of stage 2 before investing in polish.
- With the chosen camera, the bottom border Wall can hide the last row of Tiles; `wall_brick_low` exists to solve this and should be checked as soon as the camera is in place.
- Treating a time-out as a Draw can prolong a passive 1v1 Match; sudden death is the known remedy if it proves annoying.
- The web build is a secondary target: check it at the end of stage 2, not only at stage 7, so an incompatibility is found while it is cheap.
